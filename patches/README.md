# Patches to upstream tools

Each folder is one numbered series, applied in file-name order by `scripts/apply-patches.ps1`
(run by `scripts/bootstrap.ps1`, and checked again by `scripts/build.ps1`). A stamp in the tool
tree records the series it carries. A patch that fails resets the tree and stops with its name.

| Folder | Applied to | Upstream revision |
|---|---|---|
| `rexglue/` | `.tools/rexglue-source` | `f5337cd` (v0.10.0) |
| `xenosrecomp/` | `.tools/xenosrecomp` | `339af41` (re:Blue fork) |

To add one, edit `.tools/rexglue-source` and run `pwsh scripts/new-patch.ps1 <name>` (for
XenosRecomp, edit `.tools/xenosrecomp` and add `-Tool xenosrecomp`): it writes
the next-numbered patch from your edits and reapplies the series to prove it. A patch is never
renumbered once committed, so a fix to an earlier patch is a new patch on top.
`pwsh scripts/apply-patches.ps1 -Reset` discards the tree's edits and reapplies the series.

## Our own

| Patch | What |
|---|---|
| `0027-refuse-unrecompiled-modules` | In a multi-module project, `LoadUserModule` refuses a module with no recompiled library (ticket 07), so `XexLoadImage` fails cleanly instead of the game faulting on unrecompiled code. |
| `0028-modules-from-own-folder` | 0027 matches by file name, so a module of the same name from another device (a DLC package's) would be wired to this build's code; modules now load only from the executable's own folder, compared as resolved by the VFS. |
| `0029-guest-swap-count` | Counts `VdSwap` calls (`rex::system::GuestSwapCount`): the guest's frame count across both Modules' Direct3D copies, which the scripted pad times its steps by. |
| `0030-io-trace` | `--io_trace` logs every successful file open and every guest thread start and exit, so a run lines up against the Oracle's log (`.tools/xenia-edge/xenia.log`). Off by default. |
| `0031-frame-shown-observer` | Calls a host observer on the GPU thread after each swap's image is the presenter's newest guest output, numbered on the `GuestSwapCount` clock, so scene runs dump exactly the frame the scripted pad's `at <frame>` names (`src/frame_dumps.h`). |
| `0032-spirv-fetch-exp-adjust-word` | The SPIR-V translator read a texture fetch's exponent adjust from fetch-constant dword 4 (where bits 12:21 are the LOD bias) instead of dword 3, so every fetch was scaled by 2^(LOD-bias bits): the practice-ground player rendered black and the court lines vanished. The DXBC translator already read dword 3. |
| `0033-gpu-debug-ps-probe` | `--gpu_debug_ps_hash/_register/_components/_after`: one pixel shader's colour 0 shows a register's components, optionally right after a chosen ucode instruction, for shaders RenderDoc cannot step (FSI). Adds a translator hook after each ALU or fetch instruction. Off unless the hash is set. |
| `0034-mask-fetch-addresses` | Masks vertex-fetch, index-base and memexport addresses to physical (`& 0x1FFFFFFF`) on the CPU side (the Vulkan and the unused D3D12 command processors) and in the SPIR-V shaders, as Xenia Edge `2fce2d8`. A fetch through a mirror window (Top Spin 4's `0xC0100100`, probably XPS) was rejected by shared memory and the draw dropped. Bumps the SPIR-V translator version. The DXBC translator is not masked (Vulkan only, ADR-0005). |
| `0035-message-box-log` | Logs each `XamShowMessageBoxUI`'s title, text, buttons and focused button at info, so a headless run's auto-answered dialogs show in the log. |
| `0036-message-box-rewriter` | `rex/kernel/xam/message_box.h`: `SetMessageBoxRewriter` lets the host change a title's message box before it shows (or before headless answers it) and fix the button the title gets. Logs each rewrite. Top Spin 4 uses it for its Xbox LIVE prompt (`src/online_unavailable.h`). |
| `0037-signin-ui-closes-unchanged` | `signin_ui_closes_unchanged` (off by default; Top Spin 4 turns it on): `XamShowSigninUI` acts as a picker the player closed. The call returns; the kernel's dispatch thread (new `KernelState::Dispatch`) waits up to 2 s for the title's next notification listener (new `notify_listeners_created`), then broadcasts `XN_SYS_UI` 1 and, 100 ms later, 0, with no `XN_SYS_SIGNINCHANGED`. The stub broadcast a sign-in change and UI 0 inside the call, before the title's listener existed, so Top Spin 4's Swing `0x888C1570` (waits for UI 1, then 0) and `0x8877B998` (waits for UI 1) never returned. The dispatch thread is joined at shutdown and runs one sign-in at a time. |
| `0038-window-hidden` | `window_hidden` (off by default): the window is never shown or raised, while the presenter and its guest output (frame dumps, patch 0031) work as usual. Smoke, scene and RenderDoc runs pass it, so a run never pops up on the owner's desktop or takes focus. |
| `0039-swap-shows-own-frame` | Each guest swap shows the Native frame with its own number (the app numbers frames by `GuestSwapCount` at Present; the GPU thread's swap number is the new `FramesShownCount`), not the frame after the previous swap's (0013). The old rule started at the newest frame and drifted by every repeat and skip, so the presenter's dump of frame N could be a neighbouring Native frame (ticket 08's player-select ramp failure). Falls back to the oldest intact frame when the GPU runs more than a frame behind, and to the next newer frame when the app published none for the swap (0040 deleted the "frame before" fallback, which the shipped lag of 1 never reached). Tested in `tests/host/test_swap_choice.cpp`. |
| `0040-swap-numbering-recovery` | Follow-up to 0039 (ticket 12). `VdSwap` counts a swap in `GuestSwapCount` only where it writes the swap packet, so an early return for an invalid front buffer no longer leaves `GuestSwapCount` and `FramesShownCount` one apart for the rest of the session. `ChooseSwapFrame` only searches upwards for a missing frame (the unreachable downward "frame before" search is gone), so the shown frame never steps back at any lag. Tested in `tests/host/test_swap_choice.cpp`. |
| `0049-version-from-own-tree` | Built as a subproject, the SDK ran `git describe` in the game's repo, so its version came from the game's tags. On the `v1.0.0` commit it called itself 1.0.0, which rewrote `sdk_version` in the manifest; on any later commit every configure stopped with "floor version (0.10) is behind tag version (1.0)". It now asks its own tree. |
| `0048-ring-reset-on-worker` | Swing's D3D device moves the GPU ring while the GPU thread runs. `InitializeRingBuffer` reset the read index but kept the old ring's write index (`CA9` at every Swing load), so the thread could run the new ring's unwritten memory up to it, and could overwrite the reset when it returned. The thread now makes the move itself between packets: the write index goes to the idle sentinel, write-back stops until the new device enables it, and buffers and waits from the old ring are abandoned. Logs `Ring init` and `Ring reset applied`. |
| `0047-prefer-discrete-gpu` | Automatic Vulkan device selection takes a discrete GPU first among devices with the same feature score, then integrated, virtual, other and software (`rex/ui/vulkan/device_order.h`). It never looked at the device type, so a hybrid laptop that lists its integrated GPU first ran the game on that (issue #2). An explicit `vulkan_device` still wins, and a device that fails to initialize still falls through to the next. Tested in `tests/host/test_device_order.cpp`. |
| `0046-profile-name` | `UserProfile::set_name` sets the profile's name (the gamertag the title reads; the app sets it from `ts4_gamertag`). The title's per-profile content folder is now always `profile/User` instead of the name, so a new gamertag keeps the saves and a name never becomes a path. |
| `0045-present-hold-repeats` | A repeat present (`present_repeat_held_vblanks`: a guest vblank with no new frame, on variable refresh or the host clock) goes out at the present hold's point after its vblank, as a new frame does, instead of at the plain present offset, and its quick paint does not move the hold. Top Spin 4's 30 fps cutaways were shown for uneven halves of each 33 ms (10 ms / 28 ms pairs), so the app had turned repeats off and the cutaways reached the display at 30 Hz. With repeats held, every present of an exhibition match after boot, cutaways included, was on the 16.7 ms step (3565 of 3565 within 1 ms, PresentMon). |
| `0044-present-hold-high-water` | 0042's hold becomes a high-water mark: a frame finishing after the hold raises it at once to cover that frame (plus 1 ms), and it comes down 2 µs a frame; capped 1 ms before the next vblank, and a frame finishing past the cap raises nothing (the pacing thread holds, presents and paints in turn, so a later hold delayed every later frame). The 95th percentile left ~1 % of frames late by design. Match play at 4x with 8x MSAA (visible PresentMon runs, from 60 s): 0.12-0.21 % of display changes off the 60 Hz step, all from frames finishing after the cap; 3x with 8x MSAA: 0-0.24 %. |
| `0043-pacing-log-hold-columns` | The swap log (`--present_pacing_log`) gains `hold_us` (0042's hold point after the guest vblank) and `done_after_vblank_us` (when the frame's paint, queued after its GPU work, completed); both empty when the present was not held. They showed that frames finish ~11 ms after their vblank at 4x with 8x MSAA because Top Spin 4 issues each frame's draws in one burst at the swap, so submitting Native's work in chunks during the frame cannot start it earlier. |
| `0042-present-hold` | `present_hold` (default on): where the display shows a present as it arrives (variable refresh, host clock; not a fixed-refresh display, where FIFO snaps to refreshes), the Vulkan presenter waits for each paced frame's paint fence and presents at a hold point after the guest vblank, the same for every frame: the 95th percentile of recent completion times plus 1 ms, between `present_pacing_offset_us` and the period less 1 ms (`rex/ui/present_hold.h`). Presents queued at vblank + 5 ms were shown whenever the GPU finished, 0.7-10.4 ms later: 14 % of display changes off the 60 Hz step at 4x with 8x MSAA on a 360 Hz VRR display, 5.4-7.0 % with the hold. |
| `0041-presented-output-capture` | `Presenter::CapturePresentedOutput(RawImage&, width, height)` (default: false; the Direct3D 12 presenter keeps it): paints the latest guest output as `PaintAndPresentImpl` would for a window of that size, with the paint config's effect and no UI drawers, into an offscreen RGBA8 image and reads it back, so a headless run (no swapchain) gets the presenter's real output. The Vulkan presenter's effect-drawing block of `PaintAndPresentImpl` became `RecordGuestOutputPaint`, shared by both; a capture paints with its own `PaintContext` (submissions, descriptors, intermediates, pipelines, built on the first capture) under its own mutex, so it never touches the swapchain painting's state, and does not use the temporal upscaler. The caller is `--ts4_dump_presented=WxH` (`src/frame_dumps.cpp`, image-quality ticket 10). |

## Carried over from WWE All Stars (ADR-0004)

`rexglue/0001` to `0026` are WWE All Stars' runtime patches at `36f5bfd`, in WWE's order, with
these left out. All of them apply cleanly to `f5337cd` without the three below.

| Left out | Why |
|---|---|
| `rexglue-online.patch` | WWE's revived online play (its game server, relay and UPnP). Top Spin 4's online is stubbed in 1.0, so nothing would use it, and it pulls in libcurl, rapidjson and miniupnpc. |
| `rexglue-net-waits.patch` | Wakes guest socket waits for WWE's online sessions. Belongs with the online patch; offline modes make no socket waits that need it. |
| `rexglue-vibration.patch` | WWE's host-side rumble mixer (WWE ADR-0017). Its rules are tuned to WWE's game state. Top Spin 4's rumble goes through the SDK's own `XamInputSetState` path; revisit if rumble turns out wrong. |

Kept despite being WWE-flavoured: `0020-tu2-update` loads a Title Update's `.xexp` from `update:\`
for every Module (TU1 here), `0021-content` keeps the save root name alive across an overlapped
`XamContentCreate`, and `0026-headless-keyboard` answers Player Creator name prompts in scene runs.

## XenosRecomp (ticket 26)

The shader pack's converter id is the hash of this series (`CMakeLists.txt`,
`scripts/convert-shaders.ps1`), so a change here makes existing packs stale.

| Patch | What |
|---|---|
| `0001-wweallstars-native` | WWE All Stars' `xenosrecomp-wweallstars.patch` at `36f5bfd`, unchanged: SvR 2011's mode (`SVR2011_RECOMP`: 32 sampler slots, COLOR0-7 interpolators, the Xenos boolean file) plus WWE's fixes for the Native renderer. |
| `0002-topspin4-inputs` | Vertex inputs POSITION2-4 and NORMAL1-4 (Top Spin 4's morph-target streams) get locations 16-22, which the Native renderer's `kInputLocations` matches; without them DXC rejected 28 vertex shaders for partial explicit locations. A 1D texture fetch becomes a 2D fetch at v = 0.5 of a width x 1 texture; `tfetch1D` and its descriptor index did not exist, so 36 pixel shaders failed. |
| `0003-dec3n-normals` | `SPEC_CONSTANT_DEC3N_NORMAL` (bit 4): normals, tangents and binormals in Xenos `k_2_10_10_10` signed normalized (D3DDECLTYPE `0x2A2187`, Top Spin 4's) decode as three signed 10-bit fields. They reached the shader as raw bits read as a float, a near-zero normal, so the match lost all sunlight. The Native renderer sets the bit for that type. |
| `0004-blend-weight-halves` | 16-bit blend weights (USHORT4N skin weights) get their half pairs swapped back after the host's 32-bit vertex swap (`tfetchBlendWeight`, mask bit 8 + index), as texcoords already were. With the halves swapped, the wrong bone dominated and the ball kids, umpire and CPU player were drawn twisted. |
| `0005-alpha-test-function` | The alpha test applies RB_COLORCONTROL's compare function (`g_AlphaFunc`, shared constants +568: bit 1 less, 2 equal, 4 greater) instead of always greater-or-equal (`clip(oC0.w - g_AlphaThreshold)`). Top Spin 4 draws hair in two passes, the second keeping the fragments below the threshold; with greater-or-equal, Federer's headband showed through his hair. |
| `0006-alpha-to-mask` | Xenos alpha to mask (`RB_COLORCONTROL` bit 4) as the emulated path computes it: per-sample alpha thresholds less a 2x2 dither offset, written to `SV_Coverage` (`SPEC_CONSTANT_ALPHA_TO_MASK`, bit 5; `g_AlphaToMask` at shared constants +572), mapped to Vulkan's standard sample positions. Host alpha-to-coverage used the driver's own pattern and thinned the Academy's foliage. |
| `0007-texel-offsets-at-scale` | A fetch instruction's texel offset into a resolved texture is in guest texels at any Resolution scale (image-quality ticket 05): the host puts the texture's scale minus 1 in bits 29-30 of its descriptor index (`XR_OFFSET_SCALE`), and `tfetch2D`, `tfetch2DBicubic` and `getWeights2D` scale offsets and weights by it, as Xenia Edge's `draw_resolution_scaled_texture_offsets`. Offsets were divided by the host size, so they would shrink by the scale. No shader in Top Spin 4's pack has a non-zero fetch offset (its blur and shadow taps are UV offsets, which scale correctly), so today only the index mask is live (`docs/research/native-renderer.md`, "Shadow map and texel offsets at scale"). |
| `0008-alpha-to-mask-8x` | Alpha to mask on a target the MSAA setting raised to 8 samples (image-quality ticket 08): alpha covered in eighths, spread over Vulkan's standard 8x positions, less the dither offset in 32nds. Xenos has no 8x, so 0006 had no case for it. |
| `0009-alpha-to-mask-8x-positions` | 0008's order `{0,4,2,6,1,5,3,7}` was a bit reversal, not the standard 8x positions: at alpha 0.5 it left the top-left quarter empty, and sample 0 (which depth resolves read) had the lowest threshold, 1/8. The thresholds now follow Vulkan's standard 8x positions as two interleaved 4x patterns (samples 1, 7, 3, 2 then 4, 0, 5, 6, quarters in the 4x order), so each half of alpha covers every quarter once and sample 0 needs 3/4, as at 4x. The Native renderer warns when a GPU lacks `standardSampleLocations`. |
| `0010-registers-past-r31` | Every shader declares r0-r63, the whole temp register file (operands are 6-bit; relative temp addressing is not translated). Only r0-r31 were declared, and Top Spin 4's Module shaders use r32 and up, so DXC rejected them. |
| `0011-vfetch-without-element` | A vertex fetch the container lists no vertex element for reads 0 (with the instruction's own 0/1 components) and is noted on stdout. The Module shaders fetch explicitly from fetch constant 95 with no elements at all; the converter read the element through the end iterator, so it named an undeclared input (`iPosition0`, `iBinormal0`) or crashed at random. The Native renderer binds inputs only from the elements, so it has nothing to bind there either. |
| `0012-memexport-discard` | A vertex shader export to a register with no interpolator (memexport: eA 32, eM0-4 33-37) writes to a local nothing reads, and is noted on stdout. Its string was read through the end iterator, which crashed the converter at random. All 64 Module shaders setup left out of the pack are memexport shaders; no host pipeline carries the memory writes out, so a Native draw with one does no export. |
